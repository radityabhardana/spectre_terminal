# Terminal UI Legacy Cleanup Design

## Goal

Make the focused Spectre terminal UI the single active presentation layer without changing its current desktop or mobile appearance, workflows, or public DOM contracts.

## Current State

- `public/index.html` loads `terminal-shell.css` before `styles-v2.css`, allowing legacy rules to override the focused terminal layer.
- The page contains 565 static inline `style` attributes and six embedded `<style>` blocks.
- Trade panel markup is inside `<head>`, which is invalid HTML.
- Appearance state is split between `razorbot_mode` on `<html>` and `theme` on `<body>`.
- A hidden theme modal and two theme controllers remain active even though E2E tests require dark mode and Geist.
- `terminal-shell.css` already defines the intended desktop and mobile layout, while `styles-v2.css` still supplies legacy base and secondary-panel styles.

## Decisions

### Visual Contract

- Preserve the current focused terminal appearance.
- Keep dark mode and Geist as fixed application-level choices.
- Preserve the three primary desktop regions: market opportunities, analysis workspace, and execution rail.
- Preserve the mobile Markets, Analysis, Queue, and Account navigation.
- Do not redesign components or change user-facing workflows in this phase.

### CSS Ownership

- Delete `styles-v2.css` and expose `terminal-shell.css` as the only local stylesheet entrypoint.
- Import reusable active component rules from `terminal-components.css` before the canonical shell rules.
- Move embedded styles and active-shell inline styles into `terminal-shell.css` using descriptive classes.
- Keep component and shell ownership explicit instead of maintaining two competing design systems.
- Do not migrate dynamic renderer styles or inactive secondary surfaces in this iteration.

### Appearance Cleanup

- Remove the anti-flash script that reads `razorbot_mode`.
- Remove the hidden appearance trigger and theme modal.
- Remove light, hacker, gold, and synthwave theme variants that no longer have a supported UI path.
- Remove both legacy theme controllers from `app.js`, including `currentTheme`, `applyTheme`, and broad `.theme-btn` handling.
- Keep language settings through the existing settings control rather than the removed appearance modal.
- Keep modal relocation behavior, but move it into a theme-independent initialization function.

### HTML Structure

- Keep metadata, fonts, scripts, and stylesheet links in `<head>`.
- Move `tradePanelModal` into `<body>`.
- Preserve IDs and global function hooks used by `app.js`.
- Replace active-shell inline event styling such as `onmouseover` and `onmouseout` with CSS states.
- Keep inline styles generated by dynamic analysis renderers out of scope.

### Accessibility

- Give the trade panel `role="dialog"`, `aria-modal="true"`, and an accessible title relationship.
- Add an accessible label to its icon-only close button.
- Mark trade execution status as a polite live region.
- Preserve keyboard focus indicators, command-palette focus trapping, Escape handling, and focus restoration.
- Preserve semantic desktop regions and mobile navigation labels.

## In-Scope Surfaces

- Global tokens and fixed appearance.
- Stylesheet ordering and shell ownership.
- Topbar and status indicators.
- Market sidebar and queue controls.
- Analysis workspace and empty state.
- Dynamic EV execution rail.
- Command palette and secondary-tools drawer shell.
- Trade panel modal.
- Theme-related markup and JavaScript cleanup.

## Out of Scope

- Redesigning the visual language.
- Fully deduplicating every retained rule in `terminal-components.css`.
- Migrating every inline style in `index.html`.
- Reworking inline styles produced by dynamic JavaScript renderers.
- Changing API endpoints, persistence, trading logic, or analysis rendering.
- Renaming IDs consumed by existing JavaScript or tests.

## Behavior Contract

The following behavior must remain unchanged:

- Dark mode and Geist are applied after reload regardless of stale appearance values in local storage.
- Desktop exposes opportunities, analysis, and execution regions.
- Market refresh and queue execution controls remain available.
- The decision spine follows entry state changes.
- `Ctrl+K` opens the command palette, Escape closes it, and focus returns to the trigger.
- Mobile navigation switches between Markets, Analysis, Queue, and Account without horizontal overflow.
- Analysis and history results render in the persistent market summary surface.
- The trade panel opens, closes, selects queue items, and exposes execution status.

## Verification Strategy

Use test-driven changes for the cleanup contract:

1. Add failing source-contract tests for canonical stylesheet order, absence of legacy theme UI/state, and valid placement of the trade dialog.
2. Make the smallest markup, CSS, and JavaScript changes needed to satisfy those tests.
3. Run existing unit tests and syntax checks.
4. Run HTMLHint against `public/index.html`.
5. Run Playwright desktop and mobile tests.
6. Verify layout bounds and horizontal overflow through existing behavioral assertions rather than brittle pixel snapshots.

## Completion Criteria

- `terminal-shell.css` is the only local stylesheet entrypoint and `styles-v2.css` no longer exists.
- No supported code path reads or writes `razorbot_mode` or `theme` for appearance.
- The hidden appearance trigger and modal are removed.
- Trade panel markup is in `<body>` and has dialog semantics.
- Active-shell embedded style blocks are removed from `index.html`.
- Active-shell controls no longer depend on inline hover handlers.
- Existing unit, syntax, HTML, desktop E2E, and mobile E2E checks pass.
- The visual hierarchy and workflow remain equivalent to the pre-cleanup terminal.
